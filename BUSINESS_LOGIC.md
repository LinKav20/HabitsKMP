# Habits: документация бизнес-логики

Актуально для текущего состояния рабочего дерева на 28 октября 2026 года.

Документ описывает фактическое поведение приложения, которое следует из кода. Нереализованные экраны и известные расхождения между интерфейсом и логикой вынесены в отдельные разделы и не смешаны с готовыми сценариями.

## 1. Текущее состояние продукта

1. Приложение хранит данные локально на устройстве.
2. Основные сущности продукта:
   1. привычка;
   2. дело — реализация сохранена в коде, но отключена для первой версии;
   3. отметка выполнения сущности за конкретную дату;
   4. оценка настроения за конкретную дату.
3. Реализованы:
   1. главная страница с недельным календарём;
   2. список привычек;
   3. отметка выполнения;
   4. оценка настроения;
   5. создание привычки;
   6. создание разового или регулярного дела — только при включённом фича-флаге;
   7. просмотр недельной истории настроения и выполнения привычек.
4. Частично реализованы или представлены заглушками:
   1. авторизация;
   2. профиль — стартовый UI и собственный навигационный хост готовы, действия меню пока отсутствуют;
   3. карточка привычки;
   4. карточка дела.
5. Пока отсутствуют:
   1. пользовательские фильтры списка;
   2. пользовательская сортировка;
   3. редактирование и удаление привычек и дел;
   4. архивирование или приостановка через пользовательский интерфейс;
   5. продуктовые напоминания о привычках и делах;
   6. синхронизация с сервером.

### 1.1. Локальные фича-флаги

1. Интерфейс `FeatureFlagsStorage`, enum `FeatureFlag` со строковыми ключами и реализация `DataStoreFeatureFlagsStorage` находятся в модуле `core:featureflags`.
2. Значения сохраняются локально в общем Preferences DataStore на Android и iOS. У каждого флага отдельный стабильный ключ; при отсутствии сохранённого значения используется значение по умолчанию.
3. Для дел используется `FeatureFlag.TODOS_ENABLED`, по умолчанию `false`.
4. При выключенном флаге дела не запрашиваются из локальной базы, вкладка `Дело` на экране создания скрыта, открытие формы и создание дела блокируются. Сохранённые дела не удаляются.
5. Пункт `Debug Menu` в debug-профиле открывает существующее дебаг-меню. В разделе `Feature flags` показываются имя, описание и переключатель каждого флага.
6. Изменения сохраняются между запусками. `GetFeatureFlagsUseCase` однократно получает все флаги: дебаг-меню и экран создания кладут полученные значения в стейт при инициализации. Подписок на изменения нет. Свитчер сохраняет значение и явно обновляет стейт дебаг-меню; остальные экраны используют свой загруженный снимок до следующей загрузки данных или создания экрана.
7. Разделы ниже, описывающие создание, отображение и перенос дел, относятся к включённому флагу.

## 2. Запуск приложения и навигация

1. При обычном запуске пользователь сразу попадает на главную страницу.
2. Наличие или отсутствие сохранённого токена сейчас не влияет на стартовый экран: в обоих случаях открывается главная страница.
3. Если глобальный сетевой слой сообщает об отсутствии авторизации, приложение открывает экран авторизации.
4. Текущий экран авторизации является технической заглушкой:
   1. показывает текст `AuthContent`;
   2. содержит кнопку перехода обратно в приложение;
   3. не выполняет реальный вход и не сохраняет токен.
5. С главной страницы доступны переходы:
   1. в профиль — стартовый экран меню внутри отдельного навигационного хоста;
   2. в создание нового задания;
   3. в карточку привычки;
   4. в карточку дела из списка — при включённом `TODOS_ENABLED`.
6. Системная кнопка или жест «Назад» возвращает на предыдущий экран стека.
7. После закрытия экрана создания главная страница перечитывает данные. Это происходит как после успешного создания, так и после обычного возврата без создания.

## 3. Главная страница

### 3.1. Текущая и выбранная дата

1. «Сегодня» определяется по системной дате и часовому поясу устройства.
2. При первом открытии выбранной датой является сегодня.
3. В верхней панели отображается:
   1. `Сегодня, <дата>` для текущего дня;
   2. `Вчера, <дата>` для предыдущего дня;
   3. `Завтра, <дата>` для следующего дня;
   4. полная дата для остальных дней;
   5. кнопка профиля.
4. Нажатие на заголовок верхней панели возвращает выбор на сегодня.
5. Дату можно выбрать нажатием на число в недельном календаре.
6. Недели начинаются с понедельника.
7. Между неделями можно перемещаться горизонтальным свайпом без заданной для пользователя конечной границы.
8. При переходе через полночь:
   1. приложение обновляет значение «сегодня»;
   2. если до смены дня был выбран сегодняшний день, выбор переносится на новый сегодняшний день;
   3. если была выбрана другая дата, она остаётся выбранной.
9. Проверка смены даты выполняется только когда приложение находится на переднем плане.

### 3.2. Период загрузки календаря

1. При открытии загружается окно из шести календарных недель:
   1. четыре полные недели до текущей;
   2. текущая неделя;
   3. следующая неделя.
2. При перелистывании календаря данные подгружаются порциями вокруг видимой недели.
3. В памяти одновременно сохраняется не более 12 недель.
4. Приложение старается не выгружать из памяти:
   1. видимую неделю и соседнее окно;
   2. неделю текущего дня;
   3. неделю выбранной даты;
   4. неделю, содержащую конец пятидневного превью, когда выбран сегодняшний день.
5. Эти ограничения относятся только к оперативному кэшу экрана. Записи в локальной базе при этом не удаляются.

### 3.3. Список привычек и дел (дела — при `TODOS_ENABLED = true`)

#### Если выбрана текущая дата

1. Рассматриваются пять дат: сегодня и четыре следующих дня.
2. Список разбивается на группы:
   1. `Сегодня`;
   2. `Завтра`;
   3. `Потом` — дни от послезавтра до четвёртого дня после сегодня.
3. Одна регулярная привычка или одно регулярное дело может появиться в нескольких группах и датах, если оно запланировано на каждую из них.
4. Группа `Сегодня` отображается всегда, поскольку в ней будет хотя бы:
   1. запланированный элемент;
   2. плашка пустого дня;
   3. кнопка оценки настроения.
5. Группа `Завтра` показывается только при наличии хотя бы одного запланированного элемента.
6. Группа `Потом` показывается только при наличии хотя бы одного запланированного элемента на соответствующие даты.
7. Пустые дни внутри групп `Завтра` и `Потом` отдельно не показываются.
8. Кнопка с плюсом находится в заголовке группы `Сегодня` и открывает экран создания нового задания.

#### Если выбрана будущая дата

1. Рассматривается только выбранная дата.
2. Для завтра используется заголовок `Завтра`.
3. Для более поздней даты используется заголовок с полной датой.
4. Если ничего не запланировано, показывается плашка `На этот день нет планов`.
5. Кнопка оценки настроения не показывается.
6. Кнопка добавления нового задания не показывается.

#### Если выбрана прошлая дата

1. Рассматривается только выбранная дата.
2. Группа получает заголовок с полной датой.
3. Если ничего не запланировано, показывается плашка `На этот день нет планов`.
4. Если настроение за эту дату не сохранено, показывается кнопка `How was your day?`.
5. Кнопка добавления нового задания не показывается.

### 3.4. Правила попадания элементов в список

1. Привычка попадает на дату, только если одновременно выполнены условия:
   1. привычка активна;
   2. дата не раньше даты создания привычки;
   3. дата не позже даты окончания, если окончание задано;
   4. день недели выбран в расписании привычки.
2. Разовое дело попадает только на сохранённую дату начала.
3. Еженедельное дело попадает на каждый выбранный день недели.
4. Ежемесячное дело попадает на каждое выбранное число месяца.
5. Ежегодное дело попадает на каждую выбранную пару «день + месяц».
6. Для регулярных дел дата создания, дедлайн и признак активности сейчас не ограничивают попадание в список.
7. Для разового дела дедлайн сам по себе не создаёт отдельное появление в списке: дело показывается на текущей сохранённой дате начала, которая может автоматически переноситься.

### 3.5. Пустое состояние

1. Текст пустого состояния: `На этот день нет планов`.
2. Вместе с текстом показывается иллюстрация пустого списка.
3. Плашка добавляется только для:
   1. сегодняшнего дня, когда выбран сегодня;
   2. отдельно выбранного завтра;
   3. отдельно выбранной любой другой даты.
4. При пятидневном превью пустое состояние не создаётся отдельно для каждого будущего дня.

### 3.6. Фильтры и сортировка

1. Элементов управления фильтрами сейчас нет.
2. Пользовательской сортировки сейчас нет.
3. Автоматический порядок внутри каждой группы:
   1. плашка пустого состояния, если она нужна;
   2. невыполненные элементы;
   3. кнопка оценки дня, если она нужна;
   4. выполненные элементы.
4. Для группы `Потом` элементы дополнительно идут по возрастанию даты отдельно внутри невыполненной и выполненной частей.
5. При одинаковой дате явной сортировки по названию, типу, времени создания или приоритету нет.
6. Источник данных формирует общий список как «сначала привычки, затем дела», но порядок внутри каждого типа база данных явно не гарантирует.

### 3.7. Отображение элемента списка

1. Для привычки показываются:
   1. выбранный эмодзи;
   2. название;
   3. индикатор выполнения.
2. Для дела показываются:
   1. название;
   2. индикатор выполнения.
3. У выполненного элемента:
   1. название зачёркнуто;
   2. название окрашено вторичным цветом.
4. В группе `Потом` дополнительно показывается конкретная дата элемента.
5. Для разового дела показывается число дней до дедлайна.
6. Число дней считается как разница между сохранённой датой начала и дедлайном.
7. При сроке меньше трёх дней перед текстом ставится знак `❗`.
8. При сроке не больше трёх дней текст выделяется акцентным цветом.
9. Нажатие на основную область элемента открывает его карточку.
10. Нажатие на круглый индикатор меняет состояние выполнения.

### 3.8. Состояния выполнения

1. Для элемента на конкретную дату хранится одно из трёх состояний:
   1. записи нет — состояние не фиксировалось;
   2. `выполнено`;
   3. `не выполнено`.
2. В обычном списке отсутствие записи визуально трактуется как невыполненное состояние.
3. Первое нажатие по отсутствующей или отрицательной отметке устанавливает `выполнено`.
4. Повторное нажатие по выполненному элементу:
   1. для привычки на прошедшей запланированной дате устанавливает явное `не выполнено`;
   2. для остальных случаев удаляет отметку и возвращает состояние «не фиксировалось».
5. Выполнение можно отметить не только сегодня, но также в прошлом и будущем.
6. Для привычки на недельной матрице кликабельны и незапланированные дни внутри периода действия; нажатие по такому дню также может создать отметку `выполнено`. Это текущее техническое поведение, а не отдельное продуктовое правило.

### 3.9. Автоматическая фиксация пропусков

1. После первичной загрузки и при смене календарного дня приложение обрабатывает прошедшие даты, находящиеся в загруженном календарном окне.
2. Для привычки:
   1. если день входил в расписание;
   2. и отметки за него не было;
   3. создаётся отметка `не выполнено`.
3. Для еженедельного, ежемесячного и ежегодного дела применяется такое же правило: отсутствующая отметка за прошедшую запланированную дату становится `не выполнено`.
4. Для разового дела используется отдельная логика переноса, описанная ниже.

### 3.10. Перенос разового дела и дедлайн

1. Автоматический перенос работает только для разового дела с дедлайном.
2. Если дата начала уже прошла, а сегодняшний день раньше дедлайна:
   1. дата начала дела переносится на сегодня;
   2. текущая карта отметок этого дела на экране очищается.
3. Если сегодня совпадает с дедлайном или позже него:
   1. дата начала переносится на дату дедлайна;
   2. уже загруженные отметки этого дела в состоянии экрана заменяются на `не выполнено`.
4. Текущая реализация выполняет перенос без проверки, было ли дело уже выполнено.
5. Разовое дело без дедлайна автоматически не переносится, однако через текущую форму создания такое дело создать нельзя: у дела всегда есть дата дедлайна.

## 4. Настроение

### 4.1. Когда предлагается оценить день

1. Оценка доступна для:
   1. сегодняшнего дня;
   2. отдельно выбранной прошедшей даты.
2. Оценка не предлагается для будущей даты.
3. Кнопка показывается только если для даты ещё нет сохранённой оценки.
4. В списке кнопка располагается после невыполненных и перед выполненными элементами.
5. Если на дате нет заданий, плашка пустого состояния располагается перед кнопкой оценки.

### 4.2. Выбор и сохранение оценки

1. Нажатие на кнопку открывает нижнюю модальную панель.
2. Пользователь выбирает значение ползунком в диапазоне от 0 до 9.
3. Начальное положение ползунка соответствует оценке около 5.
4. Перед отображением и сохранением значение округляется до ближайшего целого.
5. Каждой оценке соответствует эмодзи:
   1. `0` — 😭;
   2. `1` — 😠;
   3. `2` — 😖;
   4. `3` — 😔;
   5. `4` — 🙁;
   6. `5` — 🙂;
   7. `6` — 😌;
   8. `7` — 😁;
   9. `8` — 🥰;
   10. `9` — 🤩.
6. Нажатие `Save` сохраняет оценку за выбранную дату и закрывает панель.
7. На одну дату хранится одна оценка. Новая запись за ту же дату заменяет предыдущую.
8. Пользовательского сценария редактирования уже сохранённой оценки сейчас нет.

## 5. Недельный календарь и статистика

1. Над списком показывается строка из семи дней выбранной недели.
2. Для каждого дня отображаются:
   1. число месяца;
   2. сокращение дня недели;
   3. эмодзи сохранённого настроения, если оно есть.
3. Выбранная дата выделяется заливкой.
4. Сегодня выделяется акцентным цветом текста, если не является выбранной датой.
5. Область над списком имеет два режима, переключаемых вертикальным жестом за ручку списка:
   1. компактный недельный режим с датами и эмодзи настроения;
   2. расширенный режим с графиком настроения и матрицей привычек.
6. В матрице привычек:
   1. каждая строка соответствует привычке;
   2. каждый столбец соответствует дню недели;
   3. `выполнено` показывается отдельным значком;
   4. `не выполнено` показывается отдельным значком;
   5. запланировано, но ещё не отмечено, показывается значком плана;
   6. день вне периода действия привычки не показывает отметку.
7. Если привычек нет, показывается текст `У вас нет привычек`.
8. График настроения:
   1. включает прошедшие дни недели;
   2. включает сегодня только после сохранения оценки;
   3. не включает будущие дни;
   4. для прошедшего дня без оценки создаёт точку со значением `0`, поэтому отсутствие оценки визуально совпадает с минимальной оценкой.

## 6. Создание нового задания

### 6.1. Общий сценарий

1. Экран называется `Новое задание`.
2. При текущем `TODOS_ENABLED = false` сразу открывается форма привычки, а переключатель вкладок скрыт.
3. При `TODOS_ENABLED = true` доступны две вкладки (изначально открыта форма привычки):
   1. `Дело`;
   2. `Привычка`.
4. Переключение вкладки создаёт новую форму со значениями по умолчанию. Введённые на предыдущей вкладке данные не сохраняются.
5. Кнопка `Создать` активна, если название не является пустой строкой.
6. Строка, состоящая только из пробелов, считается непустым названием и проходит проверку.
7. Максимальная длина названия и проверка уникальности отсутствуют.
8. При успехе:
   1. показывается уведомление `Success`;
   2. экран закрывается;
   3. главная страница обновляет данные.
9. При ошибке показывается уведомление `Failed`, экран остаётся открытым.

### 6.2. Создание привычки

1. Поля привычки:
   1. название;
   2. эмодзи;
   3. дни недели;
   4. бесконечная или конечная длительность.
2. Значения по умолчанию:
   1. название пустое;
   2. эмодзи `🥰`;
   3. выбраны понедельник–пятница;
   4. привычка бесконечная.
3. Нажатие на всю плашку эмодзи открывает нижнюю модальную панель и убирает фокус с поля ввода:
   1. первой открывается подборка «Для привычек»: 59 уникальных эмодзи в фиксированном порядке — вода и питание, движение и энергия, сон и отдых, здоровье и уход, учёба и фокус, деньги, природа, магия и настроение; текущий выбранный эмодзи не меняет состав и порядок подборки;
   2. полный каталог доступен через девять категорий в горизонтальном списке: занятия, предметы, еда и напитки, животные и природа, путешествия и места, символы, флаги, люди и тело, смайлики и эмоции; полные названия соответствуют группам каталога Emoji.kt и переведены в ресурсах приложения;
   3. сетка подстраивает число колонок под ширину экрана; текущий выбор выделен; затухание нижнего края показывает, что ниже есть ещё эмодзи, и исчезает в конце списка;
   4. нажатие на эмодзи выбирает его и закрывает панель;
   5. закрытие крестиком, свайпом вниз за заголовок, нажатием снаружи или системной кнопкой «Назад» не меняет выбор; прокрутка сетки в обе стороны, в том числе у её границ, не двигает панель; светлый маркер сверху не реагирует на нажатие;
   6. эмодзи отображаются системным шрифтом; поиск и история недавних пока отсутствуют.
4. Любой день недели можно включить или исключить.
5. Разрешено сохранить привычку без единого выбранного дня недели. Такая привычка не появится в обычном списке.
6. Дата начала привычки автоматически равна дате создания и отдельно не настраивается.
7. Бесконечная привычка сохраняется без даты окончания.
8. Если бесконечность выключить:
   1. по умолчанию подставляется дата через один месяц от текущей;
   2. дату можно выбрать явно;
   3. дата не может быть раньше сегодня;
   4. вместо даты можно указать количество дней до окончания;
   5. допускается `0`, что означает окончание сегодня;
   6. из значения количества дней удаляются все символы, кроме цифр.
9. Пустое или некорректное количество дней устанавливает в форме отсутствие дедлайна; отдельной проверки согласованности с выключенным переключателем нет.
10. Созданная привычка получает уникальный идентификатор и признак `активна`.

### 6.3. Создание разового дела при `TODOS_ENABLED = true`

1. Значения по умолчанию:
   1. название пустое;
   2. дедлайн — через семь дней от сегодня;
   3. дата начала — сегодня;
   4. режим `Регулярное` выключен.
2. Дедлайн обязателен и не может быть выбран раньше сегодня.
3. Дата начала не может быть выбрана раньше сегодня.
4. При изменении даты начала проверяется правило `дата начала ≤ дедлайн`.
5. Если новая дата начала позже дедлайна:
   1. изменение отклоняется;
   2. показывается сообщение об ошибке.
6. Обратная проверка сейчас отсутствует: после выбора будущей даты начала можно изменить дедлайн на более ранний и сохранить такую комбинацию.
7. После создания дело получает уникальный идентификатор, дату создания и признак `активно`.

### 6.4. Создание регулярного дела при `TODOS_ENABLED = true`

1. Включение переключателя `Регулярное` переводит форму в ежемесячный режим без выбранных дней.
2. Выключение регулярности переводит форму в разовый режим с датой начала «сегодня».
3. Повторное переключение сбрасывает ранее выбранное расписание.
4. Доступные режимы повторения:
   1. еженедельно;
   2. ежемесячно;
   3. ежегодно.
5. Для еженедельного повторения:
   1. по умолчанию выбран понедельник;
   2. можно выбрать несколько дней недели;
   3. пустой набор запрещает создание.
6. Для ежемесячного повторения можно независимо включить:
   1. первый день месяца;
   2. последний день месяца;
   3. одно или несколько конкретных чисел месяца.
7. Пункты ежемесячного расписания визуально оформлены как радиокнопки, но логически не являются взаимоисключающими.
8. Для ежегодного повторения можно добавить несколько пар «день + месяц» и удалить любую из них.
9. Пустое расписание регулярного дела запрещает создание и вызывает сообщение об ошибке.
10. Дедлайн присутствует в форме регулярного дела, но текущая логика показа и повторения его не учитывает.

## 7. Карточки привычки и дела

1. Нажатие на элемент списка открывает маршрут соответствующей карточки и передаёт идентификатор элемента.
2. Карточка привычки сейчас показывает только текст `Hello habit`.
3. Карточка дела показывает только текст `Hello todo`. При выключенном `TODOS_ENABLED` дела отсутствуют в списке главного экрана.
4. Переданный идентификатор не загружается в состояние карточки: состояние инициализируется пустой строкой.
5. Просмотр данных, статистика отдельного элемента, редактирование, удаление и архивирование не реализованы.

## 8. Профиль, тема и язык

### 8.1. Стартовый экран

1. Нажатие на кнопку профиля на главной странице открывает экран с заголовком «Профиль» / `Profile` и кнопкой «Назад».
2. Меню состоит из двух блоков со скруглёнными углами:
   1. «Все привычки» / `All habits` и «Дневник настроения» / `Mood diary`;
   2. «Тема приложения» / `App theme` и «Язык приложения» / `App language`.
3. Только в debug-сборке в конец второго блока добавляется `Debug Menu`.
4. Пункт `Debug Menu` открывает дебаг-меню с локальными переключателями флагов внутри навигационного стека профиля. Кнопка и системный жест «Назад» возвращают в профиль. Остальные пункты меню пока без действий.
5. Меню прокручивается по вертикали. Внизу экрана отдельно от прокручиваемого содержимого закреплена подпись из двух строк:
   1. `Flinkou Production`;
   2. `версия <номер>` / `version <номер>`.
6. Номер версии берётся из `currentEnvironment.appVersion`: на Android — из `PackageInfo.versionName`, на iOS — из `CFBundleShortVersionString`. При отсутствии значения показывается `Unknown`.
7. Подпись выровнена по центру, использует вторичный цвет текста и учитывает нижний системный отступ.
8. Тексты профиля вынесены в русские и английские ресурсы. Цвета фона, карточек, текста и разделителей берутся из `HabitTheme`, включая тёмную тему.

### 8.2. Навигационный хост

1. Контракты находятся в `features:profile:api`, реализации и регистрация зависимостей — в `features:profile:impl`.
2. `MainNavigationChild.Profile` содержит `ProfileNavComponent`. Родительский `MainNavContentImpl` отображает его через `ProfileNavContent`.
3. `DefaultProfileNavComponent` владеет собственным `StackNavigation<ProfileNavigationConfig>`. `ProfileNavContentImpl` отображает дочерние страницы через `Children` по тому же паттерну, что и главный хост.
4. Сейчас в стеке предусмотрен единственный маршрут `ProfileNavigationConfig.Profile`, которому соответствуют `ProfileComponent` и `ProfileContent`. Остальные страницы ещё не добавлены.
5. Обработчик «Назад» сначала пытается удалить текущую страницу из стека профиля. Если в стеке осталась только стартовая страница, вызывается родительский callback, закрывающий профиль. Для системного возврата включён `handleBackButton`.
6. Маршрут профиля в главном стеке и конфигурация внутреннего стека сериализуемы. Зависимости профиля регистрирует `profileFeatureModule()`, подключённый в `initKoin`.

### 8.3. Общий блок меню

1. Пункт описывается моделью `MenuItem(title: String, action: () -> Unit)`.
2. `ProfileMenuBlock(items, modifier)` строит общий контейнер `Box` со скруглением и фоном `surfaceContainerLowest`; внутри располагается `Column` с пунктами.
3. Разделитель рисуется только между соседними пунктами. Используется цвет `surfaceContainerHighest` и боковые отступы `16.dp`.
4. Нажатие на ячейку вызывает её `action`. Ячейка имеет семантику кнопки; эффект нажатия обрезается по форме блока.
5. У ячеек боковые отступы `22.dp` и вертикальные `12.dp`. Минимальная высота — `56.dp` для блока из нескольких пунктов и `68.dp` для одиночного пункта. Общего внутреннего отступа у контейнера нет.
6. Внешние отступы меню и расстояние между блоками — `24.dp`.

### 8.4. Определение debug-сборки

1. Видимость `Debug Menu` определяется через `currentEnvironment.isDebug`.
2. На Android проверяется `ApplicationInfo.FLAG_DEBUGGABLE` установленного приложения; на iOS используется `Platform.isDebugBinary`.
3. В release-сборке пункт отсутствует. Этот пункт пока не открывает техническое debug-меню, описанное в разделе 10.

### 8.5. Тема и язык

1. На уровне хранилища предусмотрены настройки темы:
   1. светлая;
   2. тёмная;
   3. системная.
2. По умолчанию используется системная тема.
3. Приложение реагирует на сохранённое изменение темы, но пункт `App theme` пока не открывает выбор темы и не изменяет хранилище.
4. На уровне хранилища предусмотрен язык. По умолчанию используется системный язык.
5. Пункт `App language` пока не открывает выбор языка и не изменяет хранилище.
6. В приложении есть русские и английские ресурсы, однако часть видимых текстов за пределами профиля захардкожена на русском или английском и не локализована.

## 9. Хранение данных

1. Привычки, дела и их отметки выполнения хранятся в одной локальной базе Room.
2. Настроение хранится в отдельной локальной базе Room.
3. Настройки, пользователь и токены хранятся в DataStore.
4. Для каждой пары `элемент + дата` может существовать только одна отметка выполнения; новая запись заменяет предыдущую.
5. Для каждой даты может существовать только одна оценка настроения; новая запись заменяет предыдущую.
6. Удаление приложения или очистка его локальных данных удалит пользовательские данные. Облачного восстановления в текущей реализации нет.

## 10. Техническое debug-меню

1. Debug-меню доступно только в debug-сборке через служебное уведомление.
2. Оно позволяет:
   1. выбрать окружение `STAGE` или `PROD`;
   2. посмотреть токен каждого окружения;
   3. скопировать токен;
   4. очистить stage-токен;
   5. очистить prod-токен;
   6. посмотреть версию ОС;
   7. посмотреть идентификатор устройства.
3. После смены окружения приложение просит перезапуск.
4. При закрытии debug-меню служебное уведомление показывается снова.

## 11. Известные расхождения и ограничения текущей реализации

1. При выборе сегодня показывается пять дней, а не настраиваемое пользователем количество.
2. Фильтры и сортировка отсутствуют, хотя архитектура списка допускает их добавление.
3. Пустые состояния не показываются для каждого пустого дня пятидневного превью.
4. Ежемесячное правило `последний день месяца` сохраняется, но проверка попадания дела на дату его не использует.
5. Если в ежемесячном правиле одновременно выбрать последний день и конкретные числа, при обратном чтении из базы конкретные числа теряются из доменной модели.
6. Регулярное дело может показываться до даты создания и после дедлайна.
7. Признак активности дела сохраняется в базе, но не используется при загрузке и показе.
8. Запрос привычек отсекает их по дате окончания, но не по признаку активности; дальнейшая проверка активности не даёт им попасть в обычный список, хотя строка такой привычки может остаться в недельной матрице без активных отметок.
9. Автоматический перенос разового дела не проверяет, было ли оно уже выполнено.
10. При автоматическом переносе очистка или замена истории выполнения выполняется прежде всего в состоянии экрана; старые записи базы явно не удаляются этим сценарием.
11. Недельный график интерпретирует отсутствие оценки за прошедший день как значение `0`.
12. Незапланированный день привычки внутри периода действия кликабелен в недельной матрице и может быть отмечен выполненным.
13. Ошибки загрузки главной страницы, подгрузки календаря и сохранения настроения не имеют пользовательского сообщения или отдельного состояния экрана.
14. После смены дедлайна дела не проверяется уже выбранная дата начала.
15. Кнопка создания проверяет только непустое название; для привычки не проверяются дни повторения и согласованность конечного срока.
16. Часть пользовательских текстов смешивает русский и английский языки.
17. Карточки элементов и реальная авторизация пока являются заглушками; в профиле реализован только стартовый UI без действий пунктов меню.
